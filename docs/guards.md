# Guards

Every guard GEL runs, with the exact rule it fails on. The short list is in the [README](../README.md#what-it-catches).

| Guard | Fails when |
| --- | --- |
| `secret-scan` | an AWS, GitHub, Anthropic, OpenAI, Stripe live or Slack key, or a private key block, is in a file (test files, sample TLS keys and doc placeholders are skipped) |
| `pinned-actions` | a workflow uses another org's action by tag or branch instead of a commit SHA |
| `workflow-permissions` | a workflow job has no `permissions` (and no top-level one), uses `write-all`, or checks out the fork's code under `pull_request_target` |
| `workflow-timeouts` | a workflow job that runs steps has no `timeout-minutes`, so a hang runs for GitHub's 360-minute default. A job that only calls a reusable workflow (`uses:`) is skipped: the timeout lives in the callee |
| `frozen-install` | a workflow installs with `npm install`, `bun install`, `yarn install`, `pnpm install` or `pip install` and no frozen form (`npm ci`, `--frozen-lockfile`, `--immutable`, `--require-hashes`), or a `package.json` with dependencies has no lockfile beside it. Global installs (`-g`) are skipped |
| `dead-links` | a markdown or HTML link points to a file that is not in the repo |
| `done-without-green` | a pull request says "all checks pass" or "ready to merge" while a check on its last commit is red |
| `migrations-append-only` | a pull request edits, renames or deletes a migration that is already on the base branch (Rails, Django, Alembic, Prisma, Knex, Drizzle, Supabase, Flyway, golang-migrate and others). Adding a migration is fine |
| `api-contract` | a pull request changes an OpenAPI or Swagger spec (JSON or YAML) so that an existing client breaks: an endpoint or method removed, a new required parameter or request body, a path parameter or a 2xx response gone |
| `tests-with-change` | a pull request changes product code and no test file in the same pull request. It reads changed paths, never the PR title. Docs, generated files, config, fixtures and test-only changes pass. Tune with `tests_with_change` (`source`, `tests`, `exempt` globs) |
| `adr-required` | opt-in: a pull request touches a path listed in `adr_required.paths` and adds no ADR (a new `.md` under `adr_required.directory`, default `docs/adr`) with Context, Decision, Alternatives and Consequences sections. `min_lane` sets the lowest risk lane that triggers it. No `paths`, no rule |
| `repo-health` | a repo has no LICENSE, SECURITY.md, CONTRIBUTING.md or CODEOWNERS (root, `.github/` or `docs/`), or its README has no sentence saying what it is for. List files the org supplies from its `.github` repo in `docs/gel.json` as `"repo_health": {"inherit": ["security", "contributing"]}` |
| `status-declared` | opt-in: `docs/gel.json` exists and has no `status` (production, active, experimental, archived) or no `owner`, or an `active` repo has had no commit for `stale_after_days` (default 365, needs `ctx.lastCommitAt`) |
| `dependabot-config` | the repo uses an ecosystem (npm, pip, go, cargo, docker, github-actions and others) that `.github/dependabot.yml` (or a Renovate config) does not cover |
| `gitattributes-eol` | a `.gitattributes` line-ending rule (`text`, `text=auto`, `eol=crlf`, `crlf`, `-binary`) lacks `eol=lf` as its only eol setting, or a file has more than 256 such rules. The Claude plugin directory refuses a repo before scanning it for these, even for `* text=auto`. `-text`, `-crlf` and bare `binary` are fine. Offline, whole tree |
| `sonar-patterns` | a file whose first line is a bash shebang tests with `[ ... ]` instead of `[[ ... ]]` (comments, heredoc bodies and `#!/bin/sh` files are skipped), or a non-test `.ts` file has a backtracking-prone regex: trailing `\s*$`, `.replace(/x+$/, ...)`, `.replace(/^x+/, ...)`, `.replace(/^x+\|x+$/g, ...)`, a `split`/`replace` regex padded with `\s*`, or lazy `(.+?)\s*$`. Freeze existing hits in `docs/gel.json` as `"sonar_patterns": {"baseline": {"scripts/x.sh": 2}}`: a file with at most its baseline count passes, any other file must be clean. Lower the numbers as files are fixed |
| `checks-green` | another check on the pull request's last commit is red (`failure`, `timed_out`, `cancelled`, `action_required`, a failed commit status), a check says it is misconfigured even though it ended green or neutral (SonarCloud "Project doesn't exist", bad credentials, an expired token), or a check was still running when GEL judged. `gel-ctx` waits up to `GEL_WAIT_SECONDS` (default 300) for the other checks to finish, because GEL starts at the same time as they do and a verdict that is not in yet is not green. Unlike `done-without-green` it does not need the PR text to claim anything. Tune with `checks_green`: `ignore` (check names), `allow_pending` |
| `deploy-delivered` | a deploy workflow (named or built like one: `wrangler`, `deploy-pages`, `npm publish`, `flyctl deploy` and others) gates its steps on a secret-backed variable being set (`if: env.X != ''`) and no step fails when it is empty, so an unset `CLOUDFLARE_API_TOKEN` gives a green run that deployed nothing; or the latest deploy run on the default branch (`ctx.deployRuns`, read by `gel-ctx`) ended `success` with every deploy step `skipped`. Fix by failing the job when the secret is empty (`exit 1`). If the skip is on purpose, list the file in `deploy_delivered.allow_skip` |
| `change-verified` | opt-in (`verify` in `docs/gel.json`): `gel verify` ran the project's own `install`, `build` and `test` on the pull request and one exited non-zero or timed out; or product code changed and `gel verify` never ran; or a changed source file, put back to its base version, still passes the tests (no test exercises the change; the check runs the tests once per changed file, at most `max_revert_files`, default 5, and skips a file with uncommitted edits). Config: `"verify": {"install": "bun install --frozen-lockfile", "build": "bun run build", "test": "node --test scripts/*.test.mjs", "source": ["src/**"], "revert_check": true, "timeout_s": 600}`. The commands run on the PR's own checkout: use the workflow under `pull_request`, never `pull_request_target` |
| `perf-budget` | opt-in (`perf_budget.command` in `docs/gel.json`): a named benchmark, run by `gel perf` (median of `runs`, default 3; the command prints a number or `{"value": n, "unit": "s"}` on its last line), is worse than the baseline in `perf_budget.baseline` (default `bench/perf-baseline.json`) by more than `tolerance` (default 0.1) in the `better` direction (`lower` default); or the command crashes or prints no number; or the baseline file is missing; or code changed and the benchmark never ran. `gel perf --update-baseline` writes the baseline. Measure the baseline on the CI runner, not a laptop: runners differ |
| `install-ignore-scripts` | mirrors SonarCloud **S6505** and **S8543**. A workflow or composite-action line runs `bun install\|add`, `npm ci\|install\|add`, `pnpm install\|add` or `yarn install\|add` without `--ignore-scripts`, or runs `npx` / `bunx` on a package with no `@version` and no `--no-install`. Global installs (`-g`) and comments are skipped. Fix: `bun install --frozen-lockfile --ignore-scripts`, `npx --no-install tsc` or `npx wrangler@3.50.0`. Freeze existing hits as `"install_ignore_scripts": {"baseline": {".github/workflows/ci.yml": 3}}` |
| `curl-https-only` | mirrors SonarCloud **S6506**. A `curl` in a workflow, a shell script or a Dockerfile has no `--proto '=https'` (a flag on a `\` continuation line counts). Skipped: comments, heredoc bodies, `curl --version`, and a curl whose every URL is localhost, 127.0.0.1, `[::1]` or 0.0.0.0. Freeze existing hits as `"curl_https_only": {"baseline": {"scripts/x.sh": 1}}` |
| `log-injection` | mirrors SonarCloud **S5145**. A line heuristic, not data flow, so keep it in `report` mode: a non-test `.ts`/`.js`/`.mjs`/`.cjs` log call (`console.*`, `log()`, `logger.*`, `core.info\|warning\|error`) that carries `error.message`, `req.body\|query\|params\|headers`, `searchParams`, `process.argv` or `github.event`; or an `::error::` / `::warning::` / `::notice::` line in a workflow or `.sh` file that interpolates `${{ github.event.* }}`, `github.head_ref`, `inputs.*`, `steps.*.outputs.*` or a `$MESSAGE`-style variable. A line that strips line breaks (`.replace(/[\r\n]/g, ...)`, `sanitize`, `JSON.stringify(`, `tr -d '\r\n'`) passes. Freeze existing hits as `"log_injection": {"baseline": {"src/a.ts": 2}}` |
| `workflow-checkout-safety` | mirrors SonarCloud **S7631**. A workflow triggered by `workflow_run` or `pull_request_target` has an `actions/checkout` step with no `persist-credentials: false`, or with a `ref:` of the PR head (`github.event.pull_request.head.*`, `github.head_ref`, `github.event.workflow_run.head_*`, `refs/pull/...`). Other triggers are not checked. Freeze existing hits as `"workflow_checkout_safety": {"baseline": {".github/workflows/x.yml": 1}}` |
| `model-deprecation` | a non-test, non-markdown source file contains a hardcoded AI model id (`@cf/...`, `gpt-...`, `claude-...`, `gemini-...`) that a provider has retired or is retiring within N days (default 30), based on `guards/model-deprecation/models.json` (id, provider, retireOn, replacement) |
| `release-integrity` | a release whose tag is not SemVer, whose commit is gone or off the default branch, with no CHANGELOG entry, a red or missing check, an earlier failed release run, or assets without checksums (or an SBOM, if required). Feed it `gel release-ctx --repo o/n --tag v1.2.3 > ctx.json`, then `gel run --ctx ctx.json`; it complements the org `release-gate` rather than replacing it |
| `five-second-test` | the first screen of a landing page (`index.html`, `public/index.html`, `docs/index.html`; set `five_second.pages` to change) cannot be understood in five seconds on a phone: no `<h1>`, a headline over 12 words, a lead over 32 words, jargon such as endpoint, inference or MCP in either, or no link or button under the headline. Offline; tune `max_h1_words`, `max_lead_words` and `jargon` under `five_second`. A page drawn by script has no headline in its source: declare `five_second.rendered` (`result`, `max_age_days`) and commit a measurement from `gel five-second --url <page> --write bench/five-second.json --merge` (headless Chrome at 375x812); the first screen the browser drew is judged by the same rules, counting only what a visitor can see (hidden, transparent, off-screen and screen-reader-only text is dropped), a headline covered by a cookie wall or popup fails, and a missing or stale measurement fails. The offline read cannot see CSS: a page that hides its real headline needs the rendered measurement |
| `cta-label` | the first `<a>`/`<button>` after the first `<h1>` (same pages and 2500-character lookup as `five-second-test`) says nothing about what the visitor gets: its visible label (tags and entities stripped, lowercased) is a bare generic (`sign in`, `sign up`, `log in`, `login`, `submit`, `continue`, `next`, `go`, `click here`, `learn more`, `read more`, `get started`, `more`, `ok`), starts with `sign in`/`sign up`/`log in`/`login`/`continue` ("Sign in with GitHub"), or is longer than 6 words. A label containing the word `free` passes the generic check ("Start free with GitHub", "Get a free API key"). No `<h1>`, no button or an icon-only link is left to `five-second-test`. Tune in `docs/gel.json`: `"cta_label": {"pages": [...], "banned": [...], "max_words": 6}`. Pages drawn by script are read from the same `five_second.rendered` measurement (`bench/five-second.json`, `entries[].html`); a missing or stale measurement is `five-second-test`'s finding, not this one's |
| `next-cta` | a landing page (same pages as `five-second-test`; `next_cta.pages` changes them) does not mark its single most likely next action. Fails when no element has `data-next-cta`; more than one has it; the marked element lacks the class (`next_cta.class`, default `next-cta`); the marked element is not the first `<a>`, `<button>`, `<input>` or `<textarea>` after the first `<h1>`; or the page defines no CSS for the class (inline `<style>` or a repo stylesheet linked with `<link rel="stylesheet">`) with an `animation` and a `prefers-reduced-motion` rule. A page with no `<h1>` is left to `five-second-test`. `next_cta.rendered` (`{ "result": "bench/five-second.json" }`) also judges the DOM a browser drew, for pages drawn by script (markup rules only). Copy the CSS from [next-cta.css](next-cta.css): a conic-gradient border spun with `@property`, colors from CSS variables, static under reduced motion. For an Astryx or other design-system page, put the class in the theme layer, not in one page |
| `agent-readiness` | a site's agent-discovery files contradict each other: `llms.txt` or `llms-full.txt` advertises a remote MCP server (`https://host/mcp`) but there is no `.well-known/mcp-server-card.json`, `.well-known/mcp/server-card.json` or `.well-known/ai-catalog.json`; a published Server Card (MCP Server Card draft) lacks `$schema`, `name`, `version`, `description` or an https `remotes[].url`; an `ai-catalog.json` is empty or an entry has neither `url` nor `data`; a published `agent-card.json` has no description or no https `supportedInterfaces` (never required: a site with no agent publishes none); or a Jekyll `_config.yml` does not `include: .well-known`, so the files would 404. Offline, whole tree |
| `north-star` | opt-in (a repo with no `docs/gel.json` is skipped): the repo's one measured headline metric is missing, stale or not met. `docs/gel.json` declares `north_star` with a `metric`, a `baseline`, a `target` (`{"ratio": 8, "better": "lower"}`), an `evidence` (how it is measured: a repo file or https link) and a `result` file (`{"value": 2.5, "baseline": 26.1, "unit": "s", "measuredAt": "..."}`). The guard fails when the result is not in the repo, is older than `max_age_days` (default 30), or `baseline / value` (`value / baseline` for `"higher"`) is under the target ratio. A claim with no number gets no pass. `gel north-star --measure` runs your `measure` command, writes `result` and exits 1 when the target is not met, so a bench workflow can gate on it. When the measure itself exits non-zero but printed a number, the number is still written (and published), the run still exits 1, and the measure's `problem` field is printed: the measure may know something the ratio cannot (a page that scrolls sideways). A measure that finds nothing prints `"value": null` with a `problem` and gel exits 2 showing it. Archived repos need none |
| `product-brief` | opt-in (applies when `docs/gel.json` has `brief` or a `north_star`): a product has not answered the six plain questions (what, who, why, how, where, when), or an answer has no number behind it. `brief` holds one entry per question with an `answer` (three words or more), a `metric`, a number `target` and optionally `"better": "lower"`; `docs/brief.json` (or `brief.result`) holds one measured number per question: `{"who": {"value": 0, "measuredAt": "2026-11-20", "source": "https://..."}}`. The guard fails when a question has no answer, metric or target, the same sentence answers two questions, a number is missing, has no `source` (a repo file or https link) or is older than `brief.max_age_days` (default 30). A target that is not met yet is not a failure: zero paying teams is an honest number. `gel brief` prints the six rows with MET or NOT MET; `gel grade` grades the brief bad, passed, good (3 of 6 targets met), high (5) or super high (6, all measured within 7 days). Archived repos need none |
| `ice-score` | an ICE table in a Markdown file (columns `I`/`Impact`, `C`/`Confidence`, `E`/`Ease` and `ICE`) does not hold up: a score is not a whole number from 1 to 10; `ICE` does not follow the table's formula (impact x confidence x ease, or their average: a table uses whichever most of its rows use, and a row that follows neither, or a table that mixes the two, is reported); a row in a later phase (`P1`, `P2`, `Later`) outscores a row in an earlier one (`P0`), so the build order contradicts the scores; or a confidence of 7 or more has no evidence (no link in the row and nothing in an `Evidence`, `Source` or `Proof` column). Blank template rows (`/10`, `[1-10]`), struck-through rows and tables inside a code fence are skipped. `gel grade` grades the tables bad, passed, good, high or super high by how many rows carry evidence. `"ice": {"evidence_from": 8}` in `docs/gel.json` moves the confidence that needs evidence (11 switches that rule off) |
| `click-map` | the measured click map of a page (`docs/click-map.json`, written by `gel click-map --url <site>/api/clicks?page=home&dev=mobile&days=30 --merge --write docs/click-map.json`) shows a product problem: more than 30% of clicks hit something that does nothing (text that looks like a button, a picture that looks like a link), or the button the page exists for (`click_map.main`) gets under 10% of the clicks. A missing or stale (30 days) measurement is reported too. A page with fewer than 20 clicks is not judged. A click map that answers only its owner (Flisk Analytics: `https://analytics.flisk.si/api/clicks?site=<site>&page=/&dev=mobile&days=30`) needs a key in `GEL_CLICKS_TOKEN`, made at analytics.flisk.si/tokens; it is sent as a Bearer header over https only (plain http just to localhost) and never written to the file. `gel grade` grades the pages bad, passed, good, high or super high by dead clicks and main-button share (high needs phones and computers measured; see `e2e/README.md`). Only for a repo whose `docs/gel.json` has `click_map` |
| `input-in-viewport` | a phone visitor cannot start: the page's first visible `<input>` or `<textarea>` ends below the first screen (a pitch, banner or animation pushed it down), so they must scroll before they can type. Layout cannot be read from source, so the guard reads a measurement: `gel input-viewport --url https://site --write bench/input-viewport.json` loads the page in headless Chrome at 375x667 and 320x568 (add `--cookie 'a=b'` for a theme or state) and records where the input ends. `docs/gel.json` may declare `input_in_viewport` (`result`, `max_age_days`, `pages`); the guard applies when it is declared or when `index.html`, `public/index.html`, `docs/index.html` or `site/index.html` contain a text input. Missing or stale measurement, no input found, or `bottom` over `height` fails. Archived repos need none |
| `risk-history` | opt-in on pull requests: a changed product file has a past that predicts trouble. Each file is scored 0 to 100 from its own git history (needs full history; a shallow clone, a push scan or a repo under `min_commits` does not apply and passes): fix and revert commits per change (up to 60), changed in the last 14 days (15), how often it changes (15), and no test in this pull request (10). It fails when a file scores `threshold` (default 60) or more, and the finding lists each part, so the number can be checked. Subjects starting `fix` or `hotfix` count as fixes and `Revert` as reverts. Tune with `risk_history` (`threshold`, `min_commits`, `weights`, `exempt`). It reads git, not the author, so a first-time contributor is not penalised |
| `worker-request-budget` | a Cloudflare Worker is eating the free plan's 100,000 requests a day, which takes every Worker on the account down until midnight UTC. An MCP connector answers a handshake (initialize, an initialized notice, tools/list) for every Claude session that has it on: a listing with 1,100 connected accounts cost 50,000 requests a day for about 100 tool calls. Traffic is not in the source, so the guard reads `gel worker-usage --account <id> --write bench/worker-usage.json` (Cloudflare GraphQL; `CLOUDFLARE_API_TOKEN` with Account Analytics: Read; add `--tool-calls citable=100` from the directory's usage page). `docs/gel.json` may declare `worker_budget` (`result`, `max_age_days` 7, `max_share` 0.25 per script, `max_total_share` 0.6, `max_requests_per_tool_call` 50, `scripts`). It applies when declared, or when a wrangler config sits beside a source file that serves `/mcp`. A missing or stale measurement, or a limit crossed, fails. Archived repos need none |
| `wrangler-observability` | `wrangler.toml`, `wrangler.json` or `wrangler.jsonc` exists and `observability.enabled` is not true, so production Worker logs are not kept. Offline, reads the config only. Repos with no wrangler configuration file are skipped |
| `stale-base` | a pull request branch was cut before the base branch changed its CI or scoring files (`.github/workflows/**`, `.github/actions/**`, `scripts/scores/**`, `Makefile`, `docs/gel.json`; tune with `stale_base.watch` and `stale_base.ignore`). Its checks then run old gates and can fail on something the base already fixed. It reads changed paths only, and a push scan passes. Fix: merge or rebase the base branch. |
| `public-env-secrets` | a variable that a bundler copies into the browser (`VITE_`, `NEXT_PUBLIC_`, `REACT_APP_`, `NUXT_PUBLIC_`, `EXPO_PUBLIC_`, `PUBLIC_`) is named like a secret: `SECRET`, `PRIVATE`, `PASSWORD`, `SERVICE_ROLE`, or an OpenAI, Anthropic, Stripe, Resend, AWS, GitHub and similar `KEY` or `TOKEN`. A git-ignored `.env` does not help: the value is in the JavaScript every visitor downloads. Publishable, anon, site and client-id names, `_URL` and `_LENGTH` settings, test files and markdown are skipped. Fix: call the vendor from a server or edge function, keep the key in a server-only variable, and rotate any key that was ever deployed |
| `queue-merge-group-parity` | a repo that runs a merge queue has a workflow that behaves differently on `merge_group`: a required check (from `queue.requiredChecks`) whose workflow has no `merge_group` trigger; a concurrency group with no `github.ref`, `github.sha` or `github.run_id` (a constant, or `github.head_ref`, which is empty on `merge_group`); a job with no `timeout-minutes`, or a `needs` chain longer than the queue's check timeout (default 60); a diff base read from `github.base_ref` or `github.event.pull_request.base.*`; bash-only syntax in a `run` step with no `shell` on a Windows job (or `mapfile`, `readarray`, `declare -A` on a macOS job). Applies when a workflow has `merge_group` or `docs/gel.json` has `queue`. Whole tree. See [Before you turn on a merge queue](queue.md) |
| `queue-cost-budget` | a `merge_group` workflow of 10 or more legs (`queue.reuse_from_legs`) or with a matrix built at run time neither reuses the pull request's passing run nor path-filters its legs, or a matrix on `merge_group` is over `queue.max_matrix_legs` (20). A run-time matrix declares its size under `queue.legs`; `queue.queue_full` holds a written reason per workflow. Whole tree |
| `queue-main-duplicates` | a workflow runs on `merge_group` and also on `push` to the default branch (`main`, `master`, `queue.default_branch`), so the commit the queue just tested is tested again. `queue.main_duplicates` holds a written reason per workflow. Whole tree |
| `queue-required-satisfiable` | online (needs `ctx.queue`, from `gel queue-ready --repo o/n` or `--snapshot`): an active ruleset rule can never be satisfied, such as a required check or code scanning tool that never reported on a `merge_group` or default-branch commit, or a `code_coverage` or `code_quality` rule with no uploader. Without a snapshot it passes |

`migrations-append-only`, `api-contract`, `tests-with-change` and `adr-required` compare a pull request with its base branch, so they run on pull requests only; a push scan passes them. `api-contract` reads a spec it understands and skips one it does not (YAML anchors, for example) rather than guess.


### next-cta recipe

Mark one element per page and copy [next-cta.css](next-cta.css):

```html
<h1>Run your AI for free</h1>
<a class="next-cta" data-next-cta href="/key">Get a free API key</a>
```

```css
@property --next-cta-angle { syntax: "<angle>"; inherits: false; initial-value: 0deg; }

.next-cta {
  --next-cta-1: var(--accent, currentColor);
  --next-cta-2: var(--accent-2, var(--next-cta-1));
  --next-cta-3: var(--accent-3, var(--next-cta-2));
  --next-cta-fill: var(--surface, Canvas);
  border: 2px solid transparent;
  border-radius: var(--radius, 8px);
  background:
    linear-gradient(var(--next-cta-fill), var(--next-cta-fill)) padding-box,
    conic-gradient(from var(--next-cta-angle), var(--next-cta-1), var(--next-cta-2), var(--next-cta-3), var(--next-cta-1)) border-box;
  animation: next-cta-spin 3s linear infinite;
}

@keyframes next-cta-spin { to { --next-cta-angle: 360deg; } }

/* Motion off: keep the marker, stop the spin. */
@media (prefers-reduced-motion: reduce) {
  .next-cta { animation: none; }
}
```
